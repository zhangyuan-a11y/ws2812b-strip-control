# WS2812B 灯带控制（ESP32 / ESP32-S3）

一份给 AI 编码助手用的 skill：把「刚焊好线、灯不亮」到「能远程调灯效」这条路走通，
并且把「不亮 / 只亮前几颗 / 颜色不对 / 闪烁」这类故障按层定位，而不是靠猜。

## 装法

```bash
git clone https://github.com/zhangyuan-a11y/ws2812b-strip-control.git \
  ~/.codex/skills/ws2812b-strip-control
```

装完新开一个对话，说「用 ws2812b-strip-control 做一条灯带」即可自动带上。
也可以显式调用：`$ws2812b-strip-control`。

直接拷目录同样有效，`git clone` 只是为了以后能 `git pull` 更新。

## 核心结论（三条硬约束）

1. **5V 灯带 + 高亮度 + 一定长度 → 必须独立 5V 供电，且与开发板共地。**
   短灯带（≤ 24 颗、≤ 1.4A）才可以直接从开发板 5V 脚取电。
2. **3.3V 数据电平对 5V 供电的 WS2812B 是临界值**（VIH ≈ 3.5V）。
   短线通常能直接驱动；出现随机闪白 / 闪绿就补 74AHCT125，别先去改代码。
3. **所有可调参数必须写进 NVS**，否则每次断电回出厂值，用户会以为「程序坏了」。

违反任意一条，产生的现象都**看起来像代码 bug**——这是这个 skill 存在的主要理由。

## 适用范围与边界

- 硬件假设：ESP32 / ESP32-S3（含 N16R8）驱动 5V 的 WS2812B 兼容灯带。
- 控制台依赖 `pyserial`，`python3 -m pip install pyserial`。
- `firmware/` 是一份**可直接编译烧录的参考实现**（GPIO 4，N16R8），用来对照和起步；
  换个板子或换个引脚时，照 `references/board-protocol.md` 的接口改就行——协议是稳定的那层，
  引脚和灯珠数是每台机器自己的事。
- 串口命令表和控制台解析规则是**成对绑定**的；换固件要同步改 `strip_console.py` 里的正则。

## 同任务的其它方案

| 想要 | 选它 | 代价 |
| --- | --- | --- |
| 任意灯效、完全可控、随时改 | 自研固件 + 本地控制台（本仓库） | 灯效要自己写 |
| 最快出效果、手机 App、生态现成 | WLED | 固件是黑盒；烧录和分区表有坑 |
| 只想有几十种现成效果 | 成品控制器（SP107E 之类） | 不可编程、不可远程 |
| 接 Home Assistant / MQTT | WLED，或自研 + MQTT | 多一层服务要维护 |
