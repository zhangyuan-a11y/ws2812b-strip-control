# 踩坑清单与失败诱因

每条都是**现象 → 诱因 → 处置**。现象写得具体一点，方便下次一眼对上号。

## A. 电气与接线

### A1 灯带型号买错：12V 的灯带用 5V 供电
**现象**：程序一切正常，灯带永远不亮。
**诱因**：WS2812B 有 5V 和 12V 两种；12V 版本内部串了电阻，5V 点不亮。
**处置**：看灯带焊点旁的丝印，必须印 `+5V`。印 `+12V` 就只能换灯带或换电源。

### A2 忘记共地
**现象**：完全随机——有时全亮、有时乱闪、有时第一颗乱色。
**诱因**：独立电源给灯带供电，但独立电源的 GND 没和开发板 GND 接在一起。数据线没有参考电平。
**处置**：数据线的信号参考是"开发板的地"。独立供电时**灯带 GND、电源 GND、开发板 GND 三者必须连通**。

### A3 用开发板的 5V 脚带整条灯带
**现象**：低亮度正常，一调亮就重启 / 闪烁 / USB 一拔就停。
**诱因**：开发板从 USB 取的电流只有几百 mA 余量，USB 口本身通常限流 500mA~1A。
**处置**：
- ≤ 24 颗、≤ 1.4A：可以直接从开发板 5V 脚取。
- 超过就上独立 5V 电源，开发板只走 USB，**两者共地**。

### A4 3.3V 数据电平临界
**现象**：随机闪白 / 闪绿，位置无规律；短灯带不明显，加长后变严重。
**诱因**：WS2812B 用 5V 供电时 VIH ≈ 0.7 × VDD ≈ 3.5V，而 MCU 输出 3.3V，处于临界。
**处置**：短线通常能直接驱动（先别加东西）。真出现随机闪白/闪绿再补 74AHCT125 之类做电平转换——**先去改代码是浪费时间**。

### A5 缺去耦电容
**现象**：上电瞬间第一颗容易坏 / 闪；亮度突变时整条抖一下。
**诱因**：灯带是感性负载，上电浪涌和亮度突变都会在电源上打坑。
**处置**：灯带电源入口并一颗 1000µF 电解电容（耐压 6.3V 以上）。

## B. 烧录与工具链

### B1 串口被占用，烧录失败
**现象**：`upload` 报端口打不开 / `Operation not permitted` / `Resource busy`。
**诱因**：本地控制台、`pio device monitor`、串口助手之一还占着串口。串口同一时刻只能一个进程用。
**处置**：烧录前先让控制台放开串口（本项目走 `curl http://127.0.0.1:8770/api/quit`），`sleep` 几秒等它真的退出，再烧；烧完重新拉起。

### B2 分区表缺校验 → 无限重启
**现象**：板载小灯在闪、看起来"程序在跑"，但功能全无；串口日志每几秒从头重来。
**诱因**：手改 / 手写的分区表 CSV 少了一段校验信息，芯片读到一半就复位，一秒重启几十次。**板载灯在复位循环里也会闪，非常具误导性。**
**处置**：用官方规范重新生成分区表；验证方式是"能不能稳定连上芯片"而不是"灯有没有闪"。

### B3 内存参数不匹配（ESP32-S3 N16R8）
**现象**：跑不起来，或 PSRAM 用不了。
**诱因**：16MB Flash + 8MB OPI PSRAM 必须显式配置，默认配置对不上。
**处置**：
```ini
board_build.flash_size          = 16MB
board_build.arduino.memory_type = qio_opi
board_build.partitions          = default_16MB.csv
board_upload.flash_size         = 16MB
build_flags = -DBOARD_HAS_PSRAM
```

### B4 日志走的是哪个 USB 口
**现象**：烧录成功但看不到日志。
**诱因**：ESP32-S3 开发板常有两个 USB 口（一个原生 USB、一个 UART 转接）。原生 USB 出日志需要 `-DARDUINO_USB_CDC_ON_BOOT=1`。
**处置**：显式打开该编译开关；先用"能不能打印"验证通路，再谈灯带。

## C. 串口协议

### C1 大帧一次灌进去会被截断
**现象**：板子回"看不懂这条命令"，而且**开头的字符丢了**（前导 `@` 之类不见）。
**诱因**：USB-CDC 的接收缓冲默认只有 **256 字节**。一帧几十颗灯珠就是几百字节，超了就从中间断。
**处置**：
- 提高接收缓冲（`Serial.setRxBufferSize(8192)`，且必须在 `begin()` 之前调用）
- 发送端切成 128 字节左右的小段，段间留 1ms 间隔
- 但仍要**限制单次命令的用途**——把高频大流量塞进串口命令行协议本身就是脆的，能用"板子自己算"就不要"电脑喂数据"

### C2 分包发送留缝
**现象**：整条基本正常，中间某几颗不定时亮起杂色。
**诱因**：驱动库按芯片一次最多 8 颗的限制分包，每包之间出现几微秒高电平，被下游灯珠当成锁存信号。
**处置**：用**整帧一次性直发**的方式（例如 SPI 模拟时序），不要分包。

## D. 渲染

### D1 每帧写入长度不一致
**现象**：复杂灯效（流动、扫描、彗星）闪；单色常亮和长亮不闪。
**诱因**：动画在渲染间隙没把整帧填满，或跳帧输出，产生"缝"。**这是算法问题，不是电源问题。**
**处置**：固定每帧写入长度、不要跳帧；用斑马纹和单色常亮对照确认（见 `diagnosis.md` 三步分离法）。

### D2 过渡步进太大，被看成频闪
**现象**：彩虹流动"不够流畅"、"颜色交替时闪"。
**诱因**：不是真的频闪，是色相/亮度的量化跳变；步进大 + 帧率高时最明显。
**处置**：把步长调小、或把周期放慢。用户的主观描述是"频率太高"，但根因常是**步长**而不是帧率。

### D3 呼吸两端生硬
**现象**：呼吸到最亮/最暗时"一顿"。
**诱因**：线性插值在端点速度突变。
**处置**：用平滑曲线（三角函数之类）做呼吸包络，端点自然"软着陆"。

## E. 状态持久化

### E1 断电就回默认
**现象**：每次上电都变回出厂亮度/灯效，用户认为"程序坏了"。
**诱因**：运行时参数只在内存里。
**处置**：每个可调参数改动时立刻写 NVS（`Preferences`）。灯珠数、亮度、灯效、颜色、呼吸快慢、电流上限、波形档、驱动档都要存。

### E2 数据量小的参数用错存储类型
**诱因**：`putUChar` 存不下超过 255 的值（例如灯珠数、毫安数）。
**处置**：灯珠数和电流上限用 `putUShort`，时间偏移用 `putInt`。

## F. 协作层面的失败诱因（同样会毁掉任务）

### F1 没有观测手段就开始改代码
最常见。改代码等于抽签。**先建观测通路**（串口 → HTTP），再动手。

### F2 把三类问题混成一类
电气 / 数据完整性 / 渲染逻辑，混着试就会一直在错的层里打转。每层都有明确判据，先分层再动手。

### F3 反复要求用户复检同一件事
用户在明确说过"线是焊的、我反复确认过了"之后，再让人查接线就是**不信任**，会直接毁掉协作。要拿新证据就换个**没用过的**验证方式（换一根短线、跳过一段灯带、只点一颗）。

### F4 让用户自己数灯珠
几十颗还行，上百颗必然数错，而且很烦。改成**按长度算**（`长度 × 每米颗数`），给个估算值再让用户微调。

### F5 用旧备份还原，把后来加的功能一起弄丢
`.bak` 文件之间没有先后关系，很容易把"最新加的功能"覆盖掉，制造出新的假 bug。
**处置**：改动前先 `git init` 建仓库，用提交回退，不要靠一堆 `.bak`。

### F6 一次问多个问题
用户会漏答其中几条，然后你在错误的前提上继续。**一次只问一个。**

### F7 网页设置留「保存」按钮
**现象**：用户改了灯珠数/亮度，没点保存就断电，回来发现设置回到旧的，认定"板子记不住"。
**诱因**：前端只改了输入框，新值停留在浏览器里；板子的 NVS 里还是旧的。
**处置**：数值型设置一律**改完就发命令**，不留保存按钮：

- 连续输入的（文本框、滑块）用 400ms 防抖；`change`/失焦时立刻补发一次，把窗口压到最小；
- 点一下就定的（± 微调、常用值）立刻发；
- 前端记住上次发出去的值，和板子当前值相同就不再发，省 NVS 擦写；
- 纯计算器的输入（例如灯带长度）另外存 `localStorage`，网页重开还在；
- 提示语直接写「已自动保存」，别让用户去找按钮。

板子侧配合：命令处理里当场 `gPrefs.put*`，别攒着一起写。
