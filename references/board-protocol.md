# 板子接口与电气参考

固件侧的约定 + 电气估算。换板子/换固件时这份表要跟着更新。

## 串口命令（115200）

| 命令 | 作用 | 存 NVS |
| --- | --- | --- |
| `n<数字>` | 灯珠数量（1~300） | 是 |
| `b<数字>` | 亮度 0~255 | 是 |
| `c<RRGGBB>` | 设单色，并自动切到"纯色常亮" | 是 |
| `f<0~18>` | 直接选灯效编号 | 是 |
| `0`~`7` | 快捷灯效 | 是 |
| `z<数字>` | 只点亮第 N 颗（定位用） | 否 |
| `a<RRGGBB>` | `z` 用的颜色 | 否 |
| `t` | 自检 | 否 |
| `w` | 显示 Wi-Fi 热点信息 | 否 |
| `?` | 帮助（含当前全部设置） | 否 |
| `k<0/1>` | 首颗启动缓冲（不吃灯珠） | 是 |
| `g<0/1>` | 第一颗红绿对调 | 是 |
| `m<毫安>` | 电流上限，`0` = 不限 | 是 |
| `s<1~8>` | 呼吸快慢，`1` 最慢（约 4.1 秒） | 是 |
| `d0~d3` | 数据脚驱动电流（5/10/20/40 mA） | 是 |
| `p0~p3` | 波形档（只在老 RMT 方式下有用） | 是 |
| `x0` / `x1` | `x0` 老 RMT 分包（每 6 颗一道缝）；`x1` 整帧直发（默认） | 否 |
| `h<0~64>` | SPI 帧头起跑缓冲字节数 | 否 |
| `y<1500~10000>` | 数据速度 kHz（默认 2500） | 否 |
| `r<1~5>` | 同一帧连发几遍 | 否 |

| # | 名字 | # | 名字 |
| --- | --- | --- | --- |
| 0 | 彩虹流动 | 10 | 跑马灯 |
| 1 | 逐颗扫描 | 11 | 双色追逐 |
| 2 | 整条呼吸 | 12 | 彩虹流星 |
| 3 | 彗星来回 | 13 | 星星闪烁 |
| 4 | 全白长亮 | 14 | 篝火 |
| 5 | 整体变色 | 15 | 警灯 |
| 6 | 关灯 | 16 | 彩虹波浪 |
| 7 | 纯色常亮 | 17 | 斑马纹（排查用） |

## NVS 键名（`Preferences`）

| 键 | 类型 | 含义 |
| --- | --- | --- |
| `n` | UShort | 灯珠数量 |
| `b` | UChar | 亮度 |
| `fx` | UChar | 灯效编号 |
| `cr` `cg` `cb` | UChar | 单色 RGB 分量 |
| `bs` | UChar | 呼吸快慢 1~8 |
| `sk` | UChar | 首颗启动缓冲 |
| `sf` | UChar | 第一颗红绿对调 |
| `ma` | UShort | 电流上限（0 = 不限） |
| `wp` | UChar | 波形档 |
| `dv` | UChar | 数据脚驱动电流档 |
| `dEn` `dOn` `dOff` `tz` | UChar / UShort / Int | 每天定时开关、开/关时刻、时区偏移 |

注意 `n` 和 `ma` 用 **UShort**——`UChar` 存不下大于 255 的值。

## 关键常量

| 名称 | 值 | 说明 |
| --- | --- | --- |
| 数据脚 | GPIO 4 | 换成别的脚要同步改接线说明 |
| 颜色顺序 | GRB | 发红出绿就是这里不对 |
| 灯珠上限 | 300 | 运行时用 `n` 改实际数量 |
| 出厂默认 | 11 颗 / 亮度 110 | |
| 分包颗数 | 6 | 驱动芯片一次最多 8 颗，留余量 |
| 帧尾低电平 | 约 400µs | 让灯带锁存 |
| Wi-Fi 热点 | 名字 `灯带遥控`，密码 `12345678` | 板子自己做 AP，手机连上打开网页 |

## 控制台 HTTP 接口

监听 `127.0.0.1:8770` 起（自动找 8770~8790 之间的空位），115200。

| 接口 | 作用 |
| --- | --- |
| `GET /api/state` | 板子状态 + 滚动日志。字段：`connected` `port` `err` `released` `log` `fx` `bri` `n` `color` `brs` `ma` `maCap` |
| `GET /api/send?cmd=XXX` | 下发一条命令（只放行白名单里的命令形状） |
| `GET /api/reconnect` | 重新找板子 |
| `GET /api/release?sec=N` | 放开串口 N 秒（给烧录留窗口） |
| `GET /api/quit` | 退出控制台 |

状态是**从串口回话里正则解析出来的**（心跳行 + `>> xxx` 应答）。改固件的输出格式必须同步改控制台的 `*_RE`。

## 烧录流程（串口只能一个进程占用）

```bash
curl -s http://127.0.0.1:8770/api/quit   # 1. 让控制台放开串口
sleep 3
pio run -e esp32-s3-devkitc-1 -t upload  # 2. 烧录
open "/path/to/控制台.app"                # 3. 重新拉起（等板子重启完再拉）
```

烧完**必须重新拉起控制台**，否则用户看到的是"什么都不响应"。

## 电气估算

**单颗**：WS2812B 5V，R/G/B 各 20mA，全白最亮约 **60mA**。

**电源容量**：`电流 ≥ 灯珠数 × 60mA × 0.8`（留 20% 余量）。

**实测参考（67 颗）**：

| 场景 | 估算电流 |
| --- | --- |
| 全白 @255 | ≈ 4.0 A |
| 全白 @150 | ≈ 2.4 A |
| 全白 @100 | ≈ 1.6 A |
| 橙色 `FF6A00` @255 | ≈ 1.9 A |
| 彩虹流动 / 呼吸 @114 | ≈ 0.3~0.9 A（波动） |

**取电分界**：≤ 24 颗（≈1.4A）可以直接从开发板 5V 脚取；再多必须独立 5V 电源 + 共地。

**估算实际耗电的意义**：固件里的 `m<毫安>` 是**电流上限**，超了会自动压暗。多条灯带并联时用它保护电源，比事后换电源便宜。

## 灯珠数量怎么算

```
颗数 = 长度(米) × 每米颗数
```

常见密度：60 颗/米、144 颗/米、200 颗/米（4mm 窄板常见）。

**别让用户数。** 给个估算值（宁多不少，剪短比补焊便宜），再用 `n` 命令微调。

## 多条灯带

| 接法 | 颗数填什么 | 电流 | 代码 |
| --- | --- | --- | --- |
| 并联 N 条 | 还是单条的颗数 | × N | 不用改 |
| 串联成一条长的 | 各条相加 | 不变 | 不用改 |

并联时每条各自从电源拉一对线，**所有 GND 必须连通**。
